# 在线沙盒真实演示数据生成

此工具仅用于 HookFlow 虚构数据演示站，不是生产业务灌数工具。文件 `seed_online_demo.py` 可独立上传运行，只需 Ubuntu 自带 Python 3 标准库，不依赖项目源码、Docker、pip、MySQL 客户端或数据库密码。

## 和静态截图的区别

默认追加 5 个全新的具名 SIMULATOR 接收端、30 条虚构事件（每场景6条），现有记录不删除、不修改：

| 场景 | 条数 | 结束状态 | 真实历史 |
| --- | --- | --- | --- |
| 积分服务：首次成功 | 6 | SUCCESS | 第1轮1次HTTP200 |
| 库存服务：重试后成功 | 6 | SUCCESS | 第1轮HTTP500、200 |
| 内置故障模拟器：最终失败 | 6 | FINAL_FAILED | 第1轮3次HTTP500 |
| 订单服务：人工新轮成功 | 6 | SUCCESS | 第1轮3次HTTP500，第2轮HTTP200 |
| 采购服务：暂停待恢复 | 6 | PAUSED | 首次HTTP500后停用本批专用端点 |

最后稳定分布为18条成功、6条最终失败、6条暂停，并非截图的五状态各6条。PENDING、DELIVERING和WAIT_RETRY属于真实调度的过渡态，运行时可能观察到，不能保证长期保留，不通过改时间戳、关闭全局调度或写SQL来伪造。暂停记录已有1次失败，不会伪装成“从未投递”。暂停组端点保持停用；在网页启用后，按正常规则继续投递。

每条payload标记fictional、demoBatch、scenario，并轮换6种事件类型。不设置过去的创建时间，事件ID由服务器生成UUID。默认产生约66次内部HTTP投递，规模有限。终态记录仍受项目正常30天清理规则约束。

## 执行前提

1. 只在部署站点的服务器运行，默认请求 `http://127.0.0.1:8080`；不接受任意远程URL，不发起外部Webhook。
2. 当前服务采用每轮最多3次、默认10/30秒退避；脚本不会修改服务配置。如果轮次上限不是3，将在核查时停止。
3. 先备份数据库及配套 `/etc/hookflow/hookflow.env`；不要把备份内容给别人。
4. 期间暂时独占模拟器，不要同时在网页发送事件、修改模式、启停新端点或让其他人联调。模拟器全局共享，脚本不能获取服务器级独占锁；会检测配置变化，但“检查再写入”不是原子锁，不能保证消除所有并发冲突。若该公开管理员站点无法确保独占，先不要运行。
5. 预检查发现任何PENDING、DELIVERING、WAIT_RETRY事件时会停止，不切换模式；PAUSED旧任务不会被启用。
6. 运行一般约1至3分钟，网络和调度慢时更久。不要关闭Workbench或重复运行。Token只在内存使用，不打印、不保存。管理员会话有效期以服务器为准。

## 安全机制及失败边界

- 只通过真实管理员API创建SIMULATOR、事件及人工新轮，验证事件详情、轮次、真实HTTP状态和分页；不轮换API Key，不访问数据库，不更换主密钥。
- 临时改变全局模拟器，正常结束恢复原配置。若检测到他人改动，不覆盖其配置，账本保存原值供核对。
- 失败或Ctrl-C时，尽力停用本次已确认创建的专用接收端，再尝试恢复配置，不删除已创建的任何历史。停用不会取消在途请求；断电、终端强制关闭、`kill -9`等无法保证执行恢复。
- 每个写请求发送前记录UNCONFIRMED。超时不自动重发，可能已在服务器生效；响应丢失时可能存在尚未取得ID的端点或事件。失败账本并非数据库事务回滚，不要删除账本后重跑。
- 同一账本目录有单进程锁；账本存在时拒绝再次灌数。刻意改用另一个state-dir会新建一批，不应作为失败重试手段。
- 账本目录默认 `~/.hookflow-demo-seed`，权限700；`record.json`权限600，只记非敏感配置、ID和操作结果，不记密码、Token或签名密钥。

上传 `seed_online_demo.py` 和可选离线检查 `test_seed_online_demo.py` 到服务器 `/home/admin/hookflow-upload/`。不放进网站目录，不使用sudo运行，不改Java或Nginx。

```bash
python3 -I /home/admin/hookflow-upload/seed_online_demo.py
```

可选离线控制流检查（两个Python文件须在同一目录）：

```bash
python3 -I /home/admin/hookflow-upload/test_seed_online_demo.py
```

## 确认准备好后再实际执行

```bash
python3 -I /home/admin/hookflow-upload/seed_online_demo.py --apply --username admin123
```

确认提示时输入 `SEED`，之后隐藏输入网站管理员密码（当前演示账号密码为用户自行设置的值），不是MySQL密码。密码不放在命令参数或文件中。运行后看是否明确输出“已完成”和“模拟器配置已恢复”；任何报错先停下，不自动重复执行。

也可首次先用每场景1条进行小批验证（不要两条实际创建命令都执行）：

```bash
python3 -I /home/admin/hookflow-upload/seed_online_demo.py --apply --username admin123 --per-group 1
```

同一账本只允许一批，默认6条方案和小批1条方案二选一。成功后网页清除筛选刷新；可按输出接收端ID查看对应组，查看payload的demoBatch辨认本批。原来的事件仍存在，全局总数会超过30。脚本不能控制前端展示所有状态的长期数量。

查看已运行账本摘要，不连服务：

```bash
python3 -I /home/admin/hookflow-upload/seed_online_demo.py --status
```
