# 持久本机开发环境

只为本机日常联调使用，不是部署方案，也不是P10故障验收脚本。Java21、Python3（macOS/Linux）、Docker及本地`mysql:8.4.13`镜像为前提。使用项目Maven Wrapper，不需要全局mvn；首次Wrapper分发包需缓存或网络，正式启动使用-o要求依赖已缓存。不要用已有测试容器的账户或主密钥。

命令从项目根目录（HookFlow/的父目录）执行，每条单独执行；任何一步报错先停止，不删除配置/数据卷试图重置。

## 首次设置

先运行无数据库副作用的安全检查：

```bash
python3 -I HookFlow/backend/scripts/test_local_dev.py
```

初始化（只能在交互终端运行，不接受管道/聊天传密码）：

```bash
python3 -I HookFlow/backend/scripts/local_dev.py init
```

提示管理员用户名（默认local-admin），两次隐藏输入自选密码。为适配现有BCrypt实现，开发入口限制密码非全空白且不超过72个UTF-8字节。初始化只创建数据库；管理员由随后正式应用首次启动创建。脚本不回显或记录密码，切勿把配置内容贴到聊天/日志。

自动生成独立数据库凭据及稳定加密主密钥，建立唯一`hookflow-local-*`容器和`hookflow-local-data-*`命名卷，数据库名/用户名均为hookflow_dev。数据库只映射127.0.0.1随机端口，每次启动读取实际映射，不使用原hookflow-p103-mysql，也不碰它的数据卷。默认不启动Redis。

## 日常启动

```bash
python3 -I HookFlow/backend/scripts/local_dev.py run
```

保持该终端运行；或者初始化成功后使用Claude桌面启动配置`hookflow-backend-local`。同一环境只有一个后端入口锁，8080已被其他进程占用则拒绝，不停止其他服务。首次init可指定`--port 8081`，后续沿用已有配置，重复init不覆盖密码、主密钥或端口。

后端地址默认http://127.0.0.1:8080。登录接口为POST /api/v1/auth/login，用户名/密码就是初始化时自己输入的值；前端不需要数据库密码/主密钥。不会预创建或打印业务API Key。此入口只启动后端，不能因此声称前端已连接。

另一个终端验证：

```bash
curl --noproxy '*' --connect-timeout 2 --max-time 5 -i http://127.0.0.1:8080/actuator/health
```

应为200、最小UP且有X-Request-Id。查看安全状态（不显示秘密）：

```bash
python3 -I HookFlow/backend/scripts/local_dev.py status
```

Ctrl-C或桌面停止服务仅向本入口的后端进程组发送TERM，数据库容器、数据卷及稳定配置保留。脚本没有删库、删除容器、删除卷、重置账户或主密钥轮换操作。

## 配置存放与恢复

配置保存在项目根`.hookflow-local/config.json`，在实际Git仓库HookFlow/之外；目录权限700，文件600，均要求当前用户所有，不依赖.gitignore保护。不会写到frontend/.env或命令参数。配置在磁盘上是**受文件权限保护的JSON明文，不是加密保险库**，包含自动生成的数据库密码、主密钥及用户输入的管理员密码；同一OS用户和管理员仍可能读取。Docker本身也会保存其数据库容器环境，这是本机开发安全边界，不承诺抵抗本机管理员。

不要上传、截图、全文打印该目录。不要删除它：密钥丢失会导致旧端点/任务密文无法解开。迁移电脑需通过自己的安全方式**一并备份该私有目录和对应MySQL持久卷**，不能仅备份库或每次重新生成主密钥。配置损坏/权限不符/卷丢失时脚本拒绝自动重建，避免静默丢失旧数据。

重复init沿用原配置：若Docker资源尚未创建可继续；原命名卷仍在而容器被手工移除，可恢复容器挂载原卷。已完成环境的卷缺失则停止，不会创建空卷冒充恢复。数据库密码后来被手改时会连接失败，不自动重置。管理员初始化不会覆盖已有管理员密码，改本机JSON不是密码重置入口。

正式应用会执行正常Flyway及后台保留清理（最新终态满30天），本入口不会禁用这些规则；“持久”指退出/重启不销毁数据库，不等于永久保留所有历史。仅使用虚构开发数据。

## 新增本机演示管理员

后端没有管理员注册HTTP接口。开发库已完成Flyway迁移后，可用专用离线工具新增管理员，不改正式业务接口，不重置任何已有账号，不连接原测试库。工具严格检查私有配置、容器/卷归属及本机绑定；使用后端同样的BCrypt和JDBC参数绑定写入摘要。密码只在终端getpass隐藏输入，经子进程标准输入传递，不出现在命令参数/日志/新配置文件。不会创建成功管理审计，属于本机开发引导，不伪装成管理员HTTP操作。

先执行四项受控检查：

```bash
python3 -I HookFlow/backend/scripts/test_create_local_admin.py
```

再验证Java21及已缓存依赖可编译助手（不连接数据库）：

```bash
python3 -I HookFlow/backend/scripts/create_local_admin.py --check
```

依赖路径复用已有Surefire XML的运行类路径，避免宿主安装Python BCrypt或用固定摘要；缺少报告时会停止，不下载新工具。所有检查通过后，在交互终端执行：

```bash
python3 -I HookFlow/backend/scripts/create_local_admin.py --username admin
```

两次隐藏输入你选择的本机演示密码。账号不存在才INSERT，存在则明确停止，绝不UPDATE/覆盖密码或撤销旧会话；并发唯一键冲突不自动重试。原初始化管理员、主密钥及私有配置不变。新增账号数据库持久保存；若后端已运行则尝试一次真实登录验证，Token不输出/不保存。后端尚不可达时只确认账号创建，不能声称已验证登录。创建后可直接在前端登录，不需重启应用。弱密码仅限本机虚构数据演示，不能用于公网或正式环境。

账号创建不会自动生成演示事件。可登录后在接收端页面新增SIMULATOR，再在模拟器/测试事件入口创建虚构事件，经正常投递生成真实列表与历史，不能以硬编码前端登录或伪造成功数据代替。

账号创建工具当前运行检查仍被分类服务阻塞，未声称四项/Java编译/真实建号通过；先按上面检查顺序实际运行，错误时停止并保留输出，不重置账号。

## 追加30条事件管理演示数据

截图中的独立原型数据不是数据库记录；当前EventsPage实际调用后端分页接口，本工具只通过正式管理员API新增真实虚构数据，不改前端、不清旧数据、不写SQL伪造状态。

先运行四项受控检查：

```bash
python3 -I HookFlow/backend/scripts/test_seed_demo_events.py
```

确保独立开发后端已启动、模拟器当前为ALWAYS_200，检查通过后执行：

```bash
python3 -I HookFlow/backend/scripts/seed_demo_events.py
```

默认读取私有配置中的初始化管理员登录，凭据只在内存使用；不显示或保存Token。也可指定新建演示账号并在交互终端隐藏输入密码：

```bash
python3 -I HookFlow/backend/scripts/seed_demo_events.py --username admin
```

只选择上面一种方式执行。工具先核对开发容器/卷归属，正式API创建独立SIMULATOR接收端，并用创建审计requestId核对HTTP服务确实连接同一开发库，然后顺序提交30次管理员测试事件（平台生成UUID），6种业务类型各5条，全部fictional。不会轮换业务Key、不投递外部URL、不修改全局模拟器模式；若当前不是ALWAYS_200就停止，避免干扰其他演示。

等待并核查30条SUCCESS/单轮一次真实HTTP200、数据库30条，以及按本批接收端筛选第一页20条/第二页10条。当前选择最小副作用路径，状态均由正常投递产生，不仿造截图的瞬时状态。已有事件保留，所以全局列表总数可能大于30。

私有目录的demo-events-30.json保存本批账本（安全事件ID/端点/请求ID，无凭据），存在时拒绝再执行，避免误操作重复加30条；HTTP写失败/超时不重试。部分失败保留已创建记录/不回滚删除历史，先核对账本再处理，不删除账本重新灌数据。创建成功后在前端清除筛选、刷新列表；可按输出的接收端ID筛选本批数据。若浏览器仍显示“独立原型/模拟数据”，当前打开的不是接入后端的运行页面，本工具不会改变静态原型。

本工具当前只完成源码/空白核查，四项检查及正式创建在执行前被分类服务阻塞；尚未实际添加30条，不能以脚本存在当作数据已写入。

## 直接写入开发数据库的多状态夹具（当前推荐）

用户要求现有事件管理接口返回五种状态，不另开快照页面。本入口直接向已通过归属校验的独立开发库追加测试夹具，不拦截API、不改接口契约，不修改或删除已有30条成功事件。旧seed_demo_events.py仍是全成功演示，**本次不要再运行旧脚本，也不使用5174快照入口**。

检查源码安全约束：

```bash
python3 -I HookFlow/backend/scripts/test_event_fixtures.py
```

检查Java21、已缓存JDBC与正式加密组件可编译（不连接数据库）：

```bash
python3 -I HookFlow/backend/scripts/seed_event_fixtures.py --check
```

以上检查通过后，追加多状态夹具：

```bash
python3 -I HookFlow/backend/scripts/seed_event_fixtures.py
```

同一事务新增5个具名SIMULATOR接收端（积分服务、库存服务、内置故障模拟器、订单服务、采购服务）及30条事件，五状态各6条，配套任务和虚构尝试历史，签名密钥沿用正式AES-GCM组件生成有效密文。暂停记录关联新建的停用库存服务，其余状态关联新建启用端；不修改现有同名接收端。只插入、不更新旧记录，不生成伪造的管理成功审计或模拟器接收记录。创建日期为本次运行时间前1～30分钟，按默认倒序位于旧演示事件之前（不含同时写入的新事件）。

事件类型统一为demo.fixture.v1，payload标注fictional及demoFixture，事件ID为evt-local-fixture-v1-001～030；虚构尝试摘要明确标注不是实际HTTP记录。这是测试数据，不是业务验收证据。PENDING的next_run_at设为约一年后；WAIT_RETRY使用本轮第一档365天延迟快照和相匹配的next_run_at，因此现有扫描器无需修改，短期不会自动推进。终态仍受正式30天保留清理影响；主动启用或人工重投也可能改变样本。
